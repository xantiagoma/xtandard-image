# ADR 0006: License policy

- Status: accepted
- Date: 2026-09-26

## Context

The project is MIT. It links many C libraries and may ship ML models. GPL/AGPL components would force the combined work's license or create distribution obligations incompatible with the project's goals.

## Decision

- Allowed in shipped artefacts: MIT, BSD-2/3, Apache-2.0, ISC, Zlib, libpng, IJG, OFL (fonts), MPL-2.0 (file-level), LGPL-2.1+/LGPL-3 **dynamically linked only** with source offer and license text shipped. LibRaw used under LGPL-2.1 (or CDDL-1.0).
- Forbidden (in `slim`, `full` and every Go module; the opt-in `gpl` image flavor is the single exception, see the 2026-09-27 amendment below): GPL, AGPL, SSPL, non-commercial or "research only" licenses, including model weights. Concretely excluded: x265 (use kvazaar), poppler (use PDFium), exiv2, GPL FFmpeg builds (`--enable-gpl`, libx264, libx265), libimagequant ≥ 2.12 (GPL-3; use quantizr), Ultralytics YOLO weights (AGPL), Ghostscript, `dssim` CLI (AGPL; own SSIM implementation instead).
- Base image extras (WP-66), all dynamically linked from `/opt/xtandard/lib` with their licence texts in `share/licenses/` and exact sources in `SOURCES.md`:
  - LibRaw 0.22.x: LGPL-2.1 (dual-licensed LGPL-2.1/CDDL-1.0; used under LGPL-2.1), https://www.libraw.org/ , https://github.com/LibRaw/LibRaw/blob/master/LICENSE.LGPL . Built without the (discontinued) GPL demosaic packs.
  - PDFium: BSD-3-Clause, https://pdfium.googlesource.com/pdfium/+/refs/heads/main/LICENSE ; prebuilt by bblanchon/pdfium-binaries (MIT build scripts), https://github.com/bblanchon/pdfium-binaries/blob/master/LICENSE . Its statically bundled third-party code (FreeType, libjpeg-turbo, OpenJPEG, lcms, libpng, zlib, ICU, abseil, agg, simdutf, fast_float, llvm-libc) is under permissive licences listed in the archive's `licenses/`.
  - ImageMagick 7: ImageMagick License (Apache-2.0 style), https://imagemagick.org/license/ . Restricted to the PSD/PSB coder by `docker/base/magick-policy.xml` (widened by WP-97 to the TGA, PCX, DDS, QOI, SGI, SUN, XBM, XPM and PAM coders, all built into MagickCore, no delegate); built with no delegate library except zlib, in particular no Ghostscript (AGPL), FFTW, DjVuLibre or AutoTrace (GPL).
  - OpenEXR 3.4.x and Imath 3.2.x: BSD-3-Clause, https://github.com/AcademySoftwareFoundation/openexr/blob/main/LICENSE.md , https://github.com/AcademySoftwareFoundation/Imath/blob/main/LICENSE.md ; OpenEXR's vendored libdeflate (MIT, https://github.com/ebiggers/libdeflate/blob/master/COPYING) and OpenJPH (BSD-2-Clause, https://github.com/aous72/OpenJPH/blob/master/LICENSE) are compiled in.
- `full` flavor (WP-70), dynamically linked or loaded, licence texts in `share/licenses/{ffmpeg,libvpx,onnxruntime,models}/`, sources in `SOURCES.md` (section "full flavor"), pins in `docker/base/versions-full.sh`:
  - FFmpeg 8.1.x: LGPL-2.1-or-later, https://ffmpeg.org/legal.html , https://git.ffmpeg.org/gitweb/ffmpeg.git/blob/HEAD:/COPYING.LGPLv2.1 . Built from the release tarball with `--disable-gpl --disable-nonfree` and without `--enable-version3`, shared libraries only (`libavcodec`, `libavformat`, `libavutil`, `libswscale`, `libavfilter`) plus the `ffmpeg`/`ffprobe` CLIs; `--disable-everything --disable-autodetect` and an explicit list of video demuxers, decoders, encoders and filters, no audio, no network, no `libpostproc` (GPL-only). The gate checks `ffmpeg -buildconf` and `ffmpeg -L`.
  - libvpx 1.17.x: BSD-3-Clause with the WebM additional IP rights grant, https://chromium.googlesource.com/webm/libvpx/+/refs/heads/main/LICENSE , https://chromium.googlesource.com/webm/libvpx/+/refs/heads/main/PATENTS . VP8/VP9 encode for GIF→WebM.
  - dav1d (BSD-2-Clause) and libaom (BSD-2-Clause + AOM Patent License 1.0) are the slim builds; FFmpeg uses them for AV1 decode and AV1-in-MP4 encode. No H.264 or HEVC encoder is built (libx264/libx265 are GPL; openh264 is deferred, ROADMAP open question 1).
  - ONNX Runtime 1.30.x: MIT, https://github.com/microsoft/onnxruntime/blob/main/LICENSE ; the official prebuilt CPU release (`onnxruntime-linux-{x64,aarch64}`), SHA256-pinned per architecture, whose statically bundled third-party code (protobuf, abseil, Eigen, flatbuffers, onnx, re2, cpuinfo, XNNPACK/pthreadpool, ...) is listed with its permissive licences in `ThirdPartyNotices.txt`, shipped next to `LICENSE`.
  - YuNet face detector `face_detection_yunet_2023mar.onnx`: MIT (Copyright (c) 2020 Shiqi Yu), https://github.com/opencv/opencv_zoo/blob/main/models/face_detection_yunet/LICENSE , fetched from a pinned opencv_zoo commit.
  - YOLOX-s object detector `yolox_s.onnx` (COCO-trained weights): Apache-2.0 (Megvii), https://github.com/Megvii-BaseDetection/YOLOX/blob/main/LICENSE , release asset `0.1.1rc0`.
  - Models ship as `<name>.onnx` + `<name>.LICENSE` in `/usr/share/xtandard/models/`; the gate refuses a model without a permissive licence file. Ultralytics YOLOv5/v8/11 weights (AGPL-3.0) stay excluded.
- Go dependencies follow the same list; checked with `go-licenses` in CI.
- `golang.org/x/image` v0.46.0 (BSD-3-Clause, released 2026-09-08), added by WP-36: WebP/BMP/TIFF decoders for the golden harness (`internal/testutil/golden`) and `font/basicfont` for the fixture generator (`testdata/gen`). Decode-only, test support; the service decodes through libvips.
- `github.com/caarlos0/env/v11` v11.4.1 (MIT, released 2026-05-01) and `github.com/goccy/go-yaml` v1.19.2 (MIT, released 2026-01-08), added by WP-04: the `XI_*` environment parser and the strict YAML config file decoder chosen in go-standards §7. Both have no transitive dependencies and are imported only by `internal/config`.
- `github.com/ebitengine/purego` v0.11.1 (Apache-2.0, released 2026-09-18, no dependencies), added by WP-71: loads ONNX Runtime with `dlopen` in `internal/detect/ort` without cgo (ADR 0010); credited in `NOTICE`.
- Source code ported or adapted from other projects keeps its licence obligations. imgproxy is **Apache-2.0** (not MIT; only imgproxy-docker-base and imagor-base are MIT): every file derived from it (for example the BMP/ICO codecs) keeps the upstream copyright header plus a modification notice, and the repository `NOTICE` file credits imgproxy and reproduces any upstream NOTICE text that applies. MIT-licensed build scripts (imgproxy-docker-base) keep their copyright notice in `docker/base/`.
- `build-deps.sh` runs a license gate that fails on any forbidden license; every image contains `/opt/xtandard/share/licenses/` and `SOURCES.md` with exact source URLs and versions.
- Test fixtures must be redistributable; licenses recorded in `testdata/LICENSES.md`.
- External tools that are only run, never linked, vendored or shipped, may carry any licence, like MinIO in `compose.test.yml`. The benchmark (WP-38, `bench/`) runs k6 (AGPL-3.0) from its unmodified `grafana/k6` image as the load generator, and Caddy (Apache-2.0) and `darthsim/imgproxy` (Apache-2.0) as services; its fixtures are generated from `testdata/gen` (CC0) at run time.
- Patent-encumbered codecs (HEVC decode/encode, H.264 encode) are a separate question from copyright licenses. Resolved 2026-09-27 (ROADMAP open questions 1 and 2): H.264 and HEVC **video** encoding (libx264, libx265) exist only in the `gpl` flavor, and their patent review is the deployer's responsibility; slim and full keep H.264/HEVC decode (FFmpeg `h264`/`hevc`, libde265) and HEIC still-image encoding through kvazaar (BSD) behind `XI_HEIC_ENCODE` (default off).

## Consequences

- Some capabilities cost more work (own BMP/ICO loaders, own SSIM, PDFium integration) or are unavailable in slim and full (H.264/HEVC video encoding, which only the `gpl` flavor has; x265-quality HEIC encoding).
- GPL components are available only through the opt-in `gpl` flavor (amendment below). Other GPL builds users make themselves are unsupported and must not be published under the project name.

## Amendment 2026-09-27: `gpl` flavor

- Status: accepted (owner decision, 2026-09-27, final).
- Reasoning: the owner does not sell this project and does not want licence purity to limit features. The GPL exclusions cost real capability (H.264 MP4 output, the format every browser and phone plays; HEVC video), while nobody is forced to take GPL code if it lives in a separate, clearly labelled image.
- Decision: add a third base image flavor (the app image built on it with `BASE_BUILDER`/`BASE_RUNTIME` inherits it), `gpl` = `full` + FFmpeg rebuilt with `--enable-gpl` + x264 (GPL-2.0-or-later, H.264 encode) + x265 (GPL-2.0-or-later, HEVC encode). It keeps everything full has (dav1d, libvpx, libaom, ONNX Runtime, models). Tags `ghcr.io/xantiagoma/xtandard-image-base:<vips>-r<G>-gpl[-builder]`, pins in `docker/base/versions-gpl.sh`. As distributed, its FFmpeg libraries and CLIs are one GPL-2.0-or-later work; the image label is `org.opencontainers.image.licenses="GPL-2.0-or-later AND MIT"` and `/opt/xtandard/share/licenses/LICENSE-GPL.md` states it, lists every component with its SPDX licence, and points to the corresponding source (`SOURCES.md` + `docker/base/`).
- What stays permissive: the Go source (MIT, and Go modules keep the MIT/BSD/Apache/ISC allowlist), and the `slim` and `full` images, which contain no GPL code, keep the `MIT` label and keep the strict licence gate with unchanged results. The gpl stages start from `full-deps`, so they never change slim or full.
- Scope: only x264, x265 and GPL FFmpeg are allowed, through an explicit allowlist (`XI_GPL_COMPONENTS` in `versions-gpl.sh`) that the licence gate reads in its gpl mode (`check-licenses.sh --allow-gpl`); AGPL, SSPL, nonfree, `--enable-version3` for a GPL-2.0 entry, unknown licences and any other GPL component still fail. poppler, exiv2 and GPL `dssim` are not added back: they were replaced (PDFium, own metadata handling, own SSIM), so there is nothing to gain. libheif is not rebuilt against x265; HEIC encoding stays on kvazaar.
- Patents: H.264 and HEVC are covered by patent pools. Neither the image nor the project grants a patent licence; whoever deploys or distributes the gpl image reviews the licences and patents that apply to them. The docs (README, `docker/base/README.md`, `LICENSE-GPL.md`) say so plainly.
- Runtime: the app picks the video encoder at startup by probing `avcodec_find_encoder_by_name` (`docs/FORMATS.md` "Video output"), so one binary serves full and gpl.

## Amendment 2026-09-27 (WP-97): long-tail inputs, Ghostscript stays out

- Status: accepted (WP-97; owner asked for the widest input support and delegated the AGPL judgement: "if you judge AGPL in a network service too risky, stop at documenting it").
- Added, all permissive and all in `slim` (so in every flavor): jxrlib (Microsoft, BSD-2-Clause) for JPEG XR, built from the 4creators commit Debian packages with Debian's and our patches (`docker/base/patches/jxrlib`), linked by the Go shim only (`internal/vips/jxr.c`), listed in `XI_COMPONENT_LICENSES`; and more ImageMagick coders (same ImageMagick licence, no new library). WBMP and ICNS are decoded by our own Go code (MIT).
- Not added: Ghostscript (AGPL-3.0), which EPS/PS/AI input needs, not even in the `gpl` flavor, whose allowlist stays x264, x265 and GPL FFmpeg. Reasons: (1) linked into the server (ImageMagick `--with-gslib`), AGPL-3.0 §13 would extend to the whole gpl image and oblige every deployer to offer the corresponding source to every network user; (2) the alternative, ImageMagick's `gs` delegate, is a program the policy forbids for every coder, and allowing it means running a full PostScript interpreter on untrusted uploads whose `-dSAFER` sandbox has a long record of bypasses (file read/write and command execution); (3) either way a crash or exploit sits inside the request-serving process. The licence gate keeps refusing `ghostscript`, `libgs.so` and `gsapi_new_instance` everywhere. If EPS is ever needed, the documented route is an external converter (Ghostscript in its own sandboxed container, called over the network), which keeps AGPL code out of this image and its licence.
